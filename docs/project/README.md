# Project Documentation

Canonical, version-controlled project documents. Read them in this order before changing code:

1. [`context.md`](context.md) — what the project is, design language, folder structure
2. [`architecture.md`](architecture.md) — routing, data layer, component patterns, caching
3. [`design-system.md`](design-system.md) — visual system, tokens, migration status
4. [`rules.md`](rules.md) — coding conventions and constraints
5. [`roadmap.md`](roadmap.md) — phased feature status

Brand references (logo system) live in [`docs/brand/`](../brand/).

Temporary AI session notes (`ai/bootstrap.md`, `ai/handoff.md`) are gitignored and
are not a source of truth. Decisions that should persist belong in these documents.
